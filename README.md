# TaskApi

Решение тестового задания C# / .NET Backend Developer: Minimal API на .NET 9, PostgreSQL и EF Core, RabbitMQ publish. Приложение создаёт, показывает, завершает и удаляет задачи. Схема БД создаётся миграцией при запуске.

## Запуск через Docker

Нужен Docker с Linux containers и Docker Compose v2. Из корня решения:

```sh
docker compose up --build -d
docker compose logs -f api
```

API доступен по адресу http://localhost:5080 после запуска приложения. RabbitMQ Management: http://localhost:15673, логин и пароль `taskapi`. PostgreSQL: localhost:55432. Все опубликованные порты привязаны к loopback. Реквизиты в конфигурации предназначены для локальной демонстрации.

Остановить приложение и инфраструктуру с сохранением данных PostgreSQL:

```sh
docker compose down
```

## Запуск без контейнера приложения

Нужен .NET SDK 9.0 или более новый; локально проверено с SDK 10.0.401. Для запуска приложения требуется ASP.NET Core Runtime 9.0. Поднять только инфраструктуру и запустить API:

```sh
docker compose up -d postgres rabbitmq --wait
dotnet restore
dotnet run --project src/TaskApi --urls http://localhost:5080
```

Настройки читаются из appsettings.json и переменных окружения .NET. Например, `ConnectionStrings__Tasks`, `RabbitMQ__HostName`, `RabbitMQ__Port`, `RabbitMQ__UserName`, `RabbitMQ__Password`, `RabbitMQ__VirtualHost`, `RabbitMQ__Capacity`.

## API

| Метод | Путь | Успех | Ошибки |
|---|---|---|---|
| POST | /tasks | 201 и созданная задача | 400 при неверном теле |
| GET | /tasks | 200, массив всех задач | — |
| PUT | /tasks/{id}/complete | 200 и завершённая задача | 400, 404, 409 |
| DELETE | /tasks/{id} | 204 | 400, 404, 409 при конкурентном изменении |

Создание:

```json
{"title":"Buy milk","priority":"High"}
```

`priority` можно опустить: будет `Medium`. Допустимы строковые `Low`, `Medium`, `High`; числовые enum-значения запрещены. `title` обязателен, содержит не более 200 символов, не может быть пустым или состоять из пробелов. При создании `isCompleted=false`, `completedAt=null`. Даты серверные, в UTC. Служебный RowVersion не выдаётся в HTTP-ответах. Примеры всех запросов — в TaskApi.http.

## Конкурентное завершение

Свойство `uint RowVersion` настроено через `IsRowVersion()` и сопоставляется с системным столбцом PostgreSQL `xmin`. EF Core добавляет исходную версию в условие UPDATE. Если два запроса прочитали одну версию, сохраняется только первый; второй получает DbUpdateConcurrencyException и ответ 409. Повторный вызов после завершения также возвращает 409, не меняя CompletedAt и не отправляя новое событие. Блокировок в коде завершения нет.

## RabbitMQ и остановка

После успешного SaveChangesAsync событие поступает в ограниченный Channel ёмкостью 256 сообщений. Один фоновый обработчик публикует его асинхронно: общий AMQP-канал не используется одновременно несколькими запросами, HTTP не ждёт брокер. Подключение ленивое: недоступность RabbitMQ не мешает старту API и сохранению задачи.

Exchange `task.events`: topic, durable. Routing key: `task.completed`. Сообщение persistent, content-type application/json:

```json
{
  "taskId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "title": "Buy milk",
  "completedAt": "2026-05-07T12:00:00+00:00",
  "priority": "High"
}
```

При ошибке отправки или переполнении очереди приложение пишет предупреждение с полным JSON события. Задача остаётся завершённой. Отмена HTTP после сохранения не отменяет принятое событие. На попытку сетевой отправки отведено 2 секунды. При следующем событии отключённое соединение создаётся заново.

При Ctrl+C/SIGTERM очередь закрывается для новых событий. На завершение публикаций отведено до 4 секунд, ещё до 1 секунды — на закрытие канала и соединения; неотправленные события логируются. Клиент RabbitMQ 7.2 может игнорировать отмену graceful close, поэтому по истечении бюджета транспорт закрывает принадлежащие ему TCP-сокеты через публичный SocketFactory и дожидается очистки операций. Compose даёт процессу 10 секунд для общей остановки хоста.

Доставка best effort, как допускает задание: нет outbox, повторной отправки, publisher confirms и гарантии exactly-once. При аварийном завершении процесса после коммита события могут потеряться. Exchange не хранит сообщения сам по себе: для ручной проверки заранее создайте очередь и binding `task.completed` в Management UI. Приложение не создаёт потребителя. Для production добавил бы transactional outbox и подтверждения брокера.

## Тесты

```sh
dotnet test
```

Нужны Docker и доступ к загрузке образов/NuGet. Testcontainers сам поднимает отдельные PostgreSQL 17 и RabbitMQ 4.1 на случайных портах и удаляет их после тестов. Тесты не используют базу или брокер из локального Compose. Первый запуск может быть дольше из-за загрузки образов.

Проверяются полный HTTP-сценарий создания и завершения с заглушкой интерфейса публикации, реальное получение JSON в RabbitMQ, конкурентные UPDATE на PostgreSQL (тест синхронизирует два сохранения одной версии), повторное завершение, сбой БД до публикации, недоступный брокер, валидация, GET и физическое удаление. Отдельные тесты управляемого транспорта проверяют ожидание публикаций, ограничение времени остановки, логирование и переполнение очереди. Регрессионные тесты воспроизводят игнорирование отмены при закрытии соединения и неудачную инициализацию обменника. Один интеграционный тест приостанавливает собственный контейнер RabbitMQ и проверяет закрытие реальных сокетов по таймауту.

Для тестов очереди без Docker:

```sh
dotnet test --filter FullyQualifiedName~RabbitMqServiceTests
```

## Миграции

Начальная миграция и snapshot включены. Для изменения схемы:

```sh
dotnet tool restore
dotnet ef migrations add MigrationName --project src/TaskApi
```

Миграции применяются автоматически при старте; это удобство для тестового задания. В production их следует запускать отдельным шагом деплоя, не выдавая API права на DDL.

## Структура

- src/TaskApi/Program.cs — регистрация компонентов и запуск.
- src/TaskApi/TaskEndpoints.cs — HTTP, валидация, завершение после проверки версии.
- src/TaskApi/TaskDbContext.cs и Migrations — схема PostgreSQL.
- src/TaskApi/Messaging/RabbitMqService.cs — очередь и жизненный цикл.
- src/TaskApi/Messaging/RabbitMqTransport.cs — соединение, канал и AMQP publish.
- tests/TaskApi.Tests — интеграционные тесты и проверки фоновой публикации.
